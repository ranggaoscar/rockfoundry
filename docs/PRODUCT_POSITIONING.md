# RockFoundry Product Positioning

## Category

**Agentic Product Discovery**

## Primary user

AI-assisted builders and vibe coders who want to turn a rough idea into a build-ready definition before using Codex, Claude Code, Cursor, or another coding agent.

## Problem

Coding agents are forced to invent missing product decisions. Those inventions become accidental requirements, hidden permissions, incorrect workflows, and data models the builder later has to undo.

## Solution

RockFoundry discovers and resolves missing decisions before coding. It combines a chat-first interface with a canonical project state, decision relationships, evidence, safe tools, contextual questioning, contradiction checks, and readiness evaluation.

## Primary outcome

A traceable handoff containing:

```text
BRD.md · PRD.md · ERD.md
```

## Differentiators

- unknown-unknown discovery;
- Decision Graph and affected-concept tracking;
- domain-specific questions rather than generic forms;
- evidence-backed requirements and provenance;
- human-in-the-loop material decisions;
- build readiness based on risk and coverage, not question count;
- vendor-neutral, open-source, local-first architecture;
- provider-neutral BYOK for OpenAI, Anthropic, Gemini, OpenRouter, Ollama, 9Router, and custom OpenAI-compatible endpoints.

## What it is not

- not a generic chatbot;
- not a static requirements questionnaire;
- not primarily a BRD/PRD/ERD generator;
- not a coding agent;
- not a hosted SaaS or project-management dashboard.

## Message hierarchy

Primary product principle:

> Before AI writes your code, make sure it isn't inventing your product.

Supporting product message:

> Find the missing decisions before they become bad code.

Use these as product principles, not as repeated marketing slogans in every screen.
