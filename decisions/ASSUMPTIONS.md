# Assumptions

These are provisional and must not be presented as user-confirmed product facts.

- The first useful target is a builder with a rough software idea and no formal product specification.
- One local operator is sufficient for V1; collaboration and remote team access are not required.
- A user may choose Mock Provider, local Ollama, or a remote BYOK provider.
- The canonical state can start with a typed JSON structure while first-class records preserve searchable decisions, messages, tools, and artifacts.
- The three primary artifacts are enough for a coding-agent handoff in V1.
- Public reference inspection is advisory and must be explicitly connected to the user's project context.
- Previous Alpha PostgreSQL data is not migrated automatically.
- Provider secret storage may begin with an OS-aware local config boundary and improve to a secure credential store without changing the product contract.

## How to treat assumptions

Strong inference becomes an assumption requiring confirmation. Weak inference becomes an open question. Unknown information remains unresolved. None of these should be silently promoted to explicit fact.
